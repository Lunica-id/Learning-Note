### User Enumeration

例えばログイン画面において、ユーザー名が違う場合は
`Invalid username or password`
と出るのに、パスワードが違う場合は
`Incorrect password`
と出る場合、そのユーザーが登録されているということが攻撃者に知られてしまう
これにより、攻撃者が調べなければいけないことが一つ減る

### prevention method

- 暗号化されていない接続でログインリクエストを送らない
- 必ずHTTPSに転送されるようにする　(たとえログイン要求をHTTPSにするようにしているとしても)
- アクセス可能な範囲(プロフィールやHTTP等)にユーザーネームやメールアドレスが開示されていないかの確認・監視
- パスワードの安全性確認に、”大文字と数字と記号1つ以上”のような方法ではなく実際によくあるパスワードのリストに照らし合わせるような方法を使う
- エラーメッセージを汎用的なものにする、必ず同じHTTPコードを返す　(エラーメッセージやHTTPコードの違いで情報を与えないために)
- 様々な状況で応答時間の違いが出ないようにする(特定の場合に特に遅くなるということが起きないようにする)
- Brute Forceの試みを防ぐ、少なくとも途中で中断できるようにする(例:IPベースのレート制限、その後のCAPTCHAテスト)
